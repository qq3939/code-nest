# M5 管理端

## 这个里程碑做了什么

管理端把前面所有能力"可视化、可操作"：看板用 Redis HyperLogLog 统计日活（12 KB 估算上亿去重，误差约 0.81%），用 Hash 记当天的阅读、点赞数，每天 00:10 归档到 `daily_stat` 表，展示近 30 天曲线（ECharts）；文章审核（待审 → 通过 / 驳回）、下架与恢复；用户搜索、封禁与解封（立即生效）；分类、标签（含合并）、敏感词的增删改；死信列表与一键重放；所有管理操作写入审计日志；"实验开关"页可以在运行时切换计数、Feed、缓存三种策略，并通过 Redis Pub/Sub 同步到所有实例。管理员账号在启动时根据 `.env` 里的 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 自动创建。

## 知识点清单

### 1. HyperLogLog 统计日活
- **是什么**：一种基数估计算法。把每个元素哈希后，观察二进制里"前导零的最大长度"来估算有多少个不同元素。Redis 的实现固定占 12 KB，标准误差 0.81%。用 Set 精确去重的话，一亿用户要几个 GB。
- **在哪**：`service/stat/StatService.java:50`（`recordVisit`，每个请求在拦截器里 PFADD，登录用户按 ID、匿名按 IP）、`:119`（`compute`，PFCOUNT）。
- **怎么验证**：`redis-cli PFCOUNT code-nest:uv:day:<yyyyMMdd>`；用 `MEMORY USAGE` 看这个 key 只有十几 KB。

### 2. 实时数据 + 每日归档
- **是什么**：当天的数据在 Redis 里实时累加，第二天凌晨由定时任务落库；看板读取时"今天实时算，过去的日子读库"。这样 Redis 里只需要保留几天的数据。
- **在哪**：`service/stat/StatService.java:71`（`archiveDay`，归档）、`:95`（`dashboard`，看板）、`web/job/ScheduledJobs.java:63`（`archiveDailyStat`）。
- **怎么验证**：打开 http://localhost:8080/admin ，看看板曲线；查 `SELECT * FROM daily_stat`。

### 3. 封禁与下架"实时生效"
- **是什么**：
  - 封禁：改写 `user:status` 缓存 + 作废全部刷新令牌（M1 讲过）。
  - 下架：文章状态改为 OFFLINE，事务提交后删除详情缓存和"文章状态缓存"，并发 ARTICLE_REMOVED 事件让 Feed 和搜索把它移除。即使 Feed 消息还没处理完，读 Feed 时也会用状态缓存过滤掉不可见的文章。
- **在哪**：`service/admin/AdminService.java:69`（`ban`）、`service/article/ArticleService.java:204`（`offline`）、`:339`（`evictCaches`）、`service/article/ArticleStatusCache.java:36`（`get`）。
- **怎么验证**：管理端下架一篇文章，刷新首页和关注页，它立即消失；跑 `IT/AuthIT.java:87`（`adminEndpointsRequireAdminAndBanTakesEffect`）。

### 4. 审计日志
- **是什么**：谁、在什么时候、对什么对象、做了什么、理由是什么。和业务操作在同一个事务里写入，业务回滚则日志也不留。
- **在哪**：`service/admin/AdminAuditService.java:23`（`log`）。
- **怎么验证**：管理端"操作日志"页。

### 5. 死信重放
- **是什么**：重放时不是发回业务交换机（会让订阅了同一个路由键的所有队列都再收到一次），而是经 retry 交换机、以原队列名为路由键，只回到原来那一个队列。
- **在哪**：`service/outbox/DeadLetterService.java:73`（`replay`）。
- **怎么验证**：跑 `IT/MessageReliabilityIT.java:50`（`failingMessageGoesToDeadLetterAndCanBeReplayed`）；或在管理端"死信"页点"重放"。

### 6. 运行时策略切换
- **是什么**：三种策略的当前值保存在每个实例的内存里（`volatile` 字段）。切换时发起实例先做收尾工作（例如离开 redis-batch 时把计数写回），然后通过 Redis Pub/Sub 通知所有实例更新。切缓存模式时清空本地缓存；切 Feed 模式时清空所有收件箱，让它们按新模式冷启动。只在 `dev-tools.enabled=true` 时开放（prod profile 关闭）。
- **在哪**：`core/config/RuntimeStrategy.java:36`（`update`）、`service/admin/StrategyService.java:53`（`update`）、`:80`（`apply`）。
- **怎么验证**：管理端"实验开关"页切换缓存模式，另一个实例的日志里出现 `strategy applied`。

### 7. 管理员初始化
- **是什么**：应用启动完成后检查管理员账号，不存在就创建。密码来自环境变量，不写在代码或 SQL 里。
- **在哪**：`web/init/StartupInitializer.java:23`（`run`）、`service/user/UserService.java:102`（`ensureAdmin`）。
- **怎么验证**：清空 user 表中的 admin 后重启后端，管理员被重新创建。

### 8. 前端权限
- **是什么**：路由守卫检查 `meta.admin`，非管理员跳回首页。但这只是体验层面的，真正的权限校验在后端拦截器（`/api/admin/**` 必须是 ADMIN）。
- **在哪**：`fe/router/index.ts`、`web/interceptor/AuthInterceptor.java:51`（`isAdmin`）。
- **怎么验证**：普通用户直接 `curl` 管理接口，返回 403。

## 面试可能怎么问

1. **统计日活有哪些方法？HyperLogLog 的原理是什么？**
   原理：Set（精确、内存大）、Bitmap（精确、要求用户 ID 连续、1 亿用户约 12 MB）、HyperLogLog（估算、12 KB）。HLL 利用哈希值前导零长度的统计特性估算基数，分 16384 个桶取调和平均降低误差。本项目：HLL，登录用户按 ID、匿名按 IP。局限：不能查询"某个用户今天来没来"；误差 0.81%；按 IP 统计匿名用户会把同一出口 IP 的多人算成一个。

2. **怎么让封禁立即生效？**
   原理：JWT 无法撤销，需要一个服务端状态。本项目：拦截器查用户状态缓存，封禁时改写缓存并作废刷新令牌。局限：每个请求一次 Redis 查询；如果 Redis 不可用，需要决定是放行还是拒绝。

3. **审计日志应该和业务在同一个事务里吗？**
   原理：同事务能保证"有操作必有日志"，但日志写入失败会导致业务失败；异步写不影响业务，但可能丢日志。本项目：同事务，因为管理操作频率低、审计要求高。局限：对高频操作应改为异步写。

4. **运行时切换策略要注意什么？**
   原理：切换不只是改一个变量，还有状态迁移（数据在旧策略的存储里）。本项目：离开 redis-batch 先写回；切 Feed 清收件箱；切缓存清本地缓存；多实例用 Pub/Sub 同步。局限：广播和收尾之间有短暂窗口，各实例策略可能不一致；只适合实验，不适合生产随意切换。

5. **前端做了权限控制，后端还需要吗？**
   原理：前端的一切都可以被绕过（直接调接口）。本项目：前端路由守卫只是体验，后端拦截器和角色校验才是真正的控制。局限：本项目只有 USER、ADMIN 两个角色，复杂场景需要 RBAC。

6. **死信重放为什么不发回原交换机？**
   原理：topic 交换机按路由键分发，可能有多个队列订阅同一个事件，只有失败的那个需要重放。本项目：经 retry 交换机、以队列名为路由键，精确回到原队列。局限：重放前要先修复导致失败的问题，否则会再次进入死信。
